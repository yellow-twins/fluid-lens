# Moving hardcoded text into language files

Languages are often added to a project late. Until then, text goes straight into
the templates — `<h2>Upcoming events</h2>`, `title="Close"` — and every one of
those strings has to be found and moved into an XLIFF file by hand before a second
language can be switched on.

`fluid-lens i18n` finds them and, with `--fix`, moves them: the text goes into the
right language file **in the language it is written in** (nothing is translated),
and the template gets an `f:translate` call in its place.

```bash
vendor/bin/fluid-lens i18n packages/                      # report
vendor/bin/fluid-lens i18n packages/ --fix --dry-run      # show the diff
vendor/bin/fluid-lens i18n packages/ --fix                # apply it
```

## What counts as hardcoded text

**Text content.** A run of text between tags counts when, ignoring Fluid
expressions, entities, digits and punctuation, at least two letters
(`--min-letters`) are left. `{event.title}`, `12,50 €` or `&nbsp;|&nbsp;` are not
reported; `Tickets`, `Read more` and `Hello {user.name}!` are.

**Attributes a visitor reads or hears** — on any element and on ViewHelpers alike:
`title`, `alt`, `placeholder`, `aria-label`, `aria-description`,
`aria-roledescription`, `aria-placeholder`, `aria-valuetext`; plus `value` of
`<input type="submit|button|reset">` and `<f:form.submit>`, `label` of
`<option>`/`<optgroup>`/`<track>`, `prependOptionLabel` of `<f:form.select>` and
`content` of `<meta name="description">` (and the Open Graph / Twitter title and
description). More attribute names can be added in the configuration — for
example `data-title` for TYPO3's backend modals.

**Not reported**, because it is not prose for a visitor or is already translated:

- the content of `<script>`, `<style>`, `<code>`, `<pre>`, `<kbd>`, `<samp>`,
  `<f:comment>`, `<f:cObject>`, `<f:argument>`, comments and CDATA sections,
- the fallback content of `<f:translate>` (and anything that is already an
  `f:translate` call),
- values a template assembles rather than words: text glued to a variable
  (`{prefix}Address`), codes in capitals with digits (`ST-2026`, `NO. 50K-001`)
  and single tokens stored in `<f:variable>` (`active`),
- texts on the ignore list and blocks marked with `@fluidlint-ignore`.

## What is reported but not moved

Some texts need a human; they are listed with the reason, and `--fix` leaves them
alone:

- **A sentence with inline markup** — `Please <a href="…">click here</a> to
  continue.` Translating the three pieces separately would lose the sentence and
  its word order, so it is reported once, as a whole. Texts in *sibling* elements
  (`<span>Date</span><span>Venue</span>`) are independent and are moved one by one.
- **A Fluid expression other than a plain variable** — `From {price ->
  f:format.currency()} per night`. Moving a ViewHelper call into a translation
  argument changes what it does.
- **A literal inside a Fluid array argument** — `aria="{label: 'Search'}"`.
- **An unquoted attribute value**, which cannot take an inline call safely.
- **A template without a language file** — see [Where the text goes](#where-the-text-goes).

## Where the text goes

| Template                                                  | Language file                                    | Referenced as |
|-----------------------------------------------------------|--------------------------------------------------|---------------|
| `<ext>/Resources/Private/…` (Templates, Partials, Layouts, mail templates, …) | `<ext>/Resources/Private/Language/locallang.xlf` | `key="…" extensionName="<ext>"` |
| `<ext>/ContentBlocks/<type>/<name>/templates/…`           | `<ext>/ContentBlocks/<type>/<name>/language/labels.xlf` | `key="LLL:EXT:<ext>/ContentBlocks/…/labels.xlf:…"` |
| anything else                                             | the file set with `--file` / `i18n.file`         | `key="LLL:EXT:…:…"` |

The extension is the nearest directory with a `composer.json` of type
`typo3-cms-extension` (its key from `extra.typo3/cms.extension-key`) or an
`ext_emconf.php` (its key from the directory name). `extensionName` makes the
label resolve from anywhere — a Partial rendered by another extension, a
`FLUIDTEMPLATE`, a mail — not only inside the extension's own plugins.

A language file that does not exist yet is created with a standard XLIFF 1.2
header (`source-language` from `--source-language`, default `en`). An existing one
gets the new `trans-unit`s appended before `</body>`, in its own indentation, so the
rest of the file — and its diff — is untouched.

## Keys

A key is the template's path plus the first four words of the text in
lowerCamelCase:

```text
Resources/Private/Templates/Event/List.html   "No upcoming events found."  →  event.list.noUpcomingEventsFound
Resources/Private/Partials/Order/Item.html    "Größe ändern"               →  order.item.groesseAendern
```

The `Templates`, `Partials` and `Layouts` folders are left out; umlauts and accents
are transliterated. Per language file:

- a label that **already exists with the same text** is reused — `Close` becomes
  `common.close` if that is already there, and the report marks it *(existing)*,
- the same text gets the same key throughout a run, across templates,
- a key already taken by a different text gets `.2`, `.3`, … appended.

## What the template looks like afterwards

```html
<!-- before -->
<h2>Upcoming events</h2>
<p>Hello {user.name}, you have {count} new messages.</p>
<button title="Close">×</button>

<!-- after -->
<h2><f:translate key="event.list.upcomingEvents" extensionName="events" /></h2>
<p><f:translate key="event.list.helloYouHaveNew" extensionName="events" arguments="{0: user.name, 1: count}" /></p>
<button title="{f:translate(key: 'common.close', extensionName: 'events')}">×</button>
```

```xml
<trans-unit id="event.list.helloYouHaveNew">
    <source>Hello %1$s, you have %2$s new messages.</source>
</trans-unit>
```

- Entities are decoded (`Fish &amp; Chips` is stored as `Fish & Chips`); f:translate
  escapes the label again on output, so the page renders the same.
- Indentation inside the text collapses to single spaces; the whitespace around it
  stays in the template, so nothing shifts.
- Plain variables become positional placeholders; a literal `%` is doubled when
  there are arguments, as TYPO3 runs the label through `vsprintf()`.
- Text content uses the tag form by default — or the inline form, if the scanned
  templates use `{f:translate(…)}` more often than `<f:translate>`; force one with
  `--style=tag|inline`. Attribute values always use the inline form.

## Templates written in another language

The text always becomes the `<source>` of the default file (`locallang.xlf`). If
your templates are written in German but the site's default language is English,
pass the language the templates are written in:

```bash
vendor/bin/fluid-lens i18n packages/ --fix --language=de
```

The text is then also written as the `<target>` of `de.locallang.xlf` (created if
needed, `target-language="de"`), so the German pages look exactly as before, and
the English `<source>` can be translated later — by hand or with a translation
service. `--language` equal to `--source-language` writes no extra file.

## Workflow

1. **Look**: `fluid-lens i18n packages/` lists every text with its line, where it
   stands (`p`, `img alt`, `f:form.submit value`), the key and language file it
   would move to — or why it needs a human.
2. **Tidy up**: add brand names and other texts that stay as they are to
   `i18n.ignore`, mark one-offs with `@fluidlint-ignore`.
3. **Preview**: `--fix --dry-run` prints a unified diff of every template and
   language file it would touch (pipe it into a file, or `git apply` it).
4. **Apply**: `--fix` writes the files, then lists what is left for a human.
   Review the result with `git diff`, as with any automatic change.
5. **Keep it clean**: run `fluid-lens i18n` in CI. It fails while hardcoded text
   remains; for an existing project, freeze today's texts with
   `--generate-baseline` and fail only on new ones with `--baseline`.

```text
Hardcoded texts
===============

 packages/shop/Resources/Private/Templates/Widget/SoldTickets.html
   → packages/shop/Resources/Private/Language/locallang.xlf
     10  th  "Event"                                          widget.soldtickets.event
     11  th  "Datum"                                          widget.soldtickets.datum
     12  th  "Tickets verkauft"                               widget.soldtickets.ticketsVerkauft
     43  p   "Keine bevorstehenden Events mit Tickets gefun…" widget.soldtickets.keineBevorstehendenEventsMit

 packages/shop/Resources/Private/Templates/Mail/Paid/Seller.html
   → packages/shop/Resources/Private/Language/locallang.xlf
     15  strong  "📦 Versand über DHL-API vorgemerkt Diese Bestell…"  manual: a sentence with inline markup; translate it as a whole by hand

Summary
-------

 49 text(s) can be moved to a language file, 2 need manual work, in 20 of 145 template(s).
 Preview the changes with --fix --dry-run, apply them with --fix.
```

`--json` gives the same per text (`file`, `line`, `kind`, `context`, `text`,
`label`, `arguments`, `key`, `existingKey`, `languageFile`, `reason`); `--sarif`
reports every text as an `i18n.hardcoded-text` warning for GitHub code scanning.

## Options and configuration

| Option | Config (`'i18n' => [...]`) | Default | Meaning |
|--------|----------------------------|---------|---------|
| `--fix` | — | off | Move the texts into the language files. |
| `--dry-run` | — | off | With `--fix`: print the diff, write nothing. |
| `--language=de` | `language` | — | Language the templates are written in; also writes `de.locallang.xlf`. |
| `--source-language=en` | `sourceLanguage` | `en` | `source-language` of newly created files. |
| `--style=tag\|inline` | `style` | prevailing form | How text content is written back. |
| `--file=…` | `file` | — | Language file for templates outside an extension (inside an extension itself). |
| `--min-letters=2` | `minLetters` | `2` | Letters a text needs to count. |
| — | `ignore` | `[]` | Texts to accept as they are; `'/…/'` is a regular expression. |
| — | `attributes` | `[]` | Further attribute names to treat as translatable. |
| `--baseline=…` | `baseline` | — | Accept the texts listed in this baseline. |
| `--generate-baseline[=…]` | — | `fluid-lens-i18n-baseline.json` | Write the current texts to a baseline and exit. |
| `--json`, `--sarif` | — | — | Machine-readable output. |

```php
'i18n' => [
    'ignore' => ['SACHSENTRANCE', 'Instagram', '/^©/'],
    'attributes' => ['data-title', 'data-content'],
    'language' => 'de',
],
```

Exit codes: `0` when no hardcoded text is left (after the baseline), `1` otherwise
— also after `--fix` while texts remain that need a human.

## Safety

- **Nothing is written without `--fix`**, and `--fix --dry-run` shows exactly what
  would be.
- **Exact positions.** The templates are not reformatted: a dedicated scanner reads
  the original source and records the byte range of every text and attribute
  value, and only those ranges are replaced.
- **Self-check.** Every rewritten template is scanned again; unless exactly the
  moved texts are gone and everything else is unchanged, that template is left as
  it was and its texts are reported as not moved.
- **Existing labels are never changed.** Units are only added; a key that exists
  is reused only when its text is identical.

## Limits

- The language of a text is not detected; `--language` says what the templates are
  written in.
- Sentences with inline markup, non-variable expressions and literals in Fluid
  arrays are left for a human (see above).
- String literals passed to Partials or ViewHelpers (`arguments="{label: 'Save'}"`,
  `then: 'Show more'`) are not inspected — they may or may not end up on the page.
- `@fluidlint-ignore` works line-based here: it skips texts on the marker's line and
  the line after it.
- Only XLIFF 1.2 files are extended.
